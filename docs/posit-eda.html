1 Posit

Variables to drop (redundant):

  • hh_no_car → keep pct_no_car
  • unemployed_count → keep unemployment_rate
  • imd_decile → keep imd_rand
  • road_length_m → keep road_density_km_per_km2
  • junction_count → keep junction_density_per_km2
  • road_link_count → highly correlated with junction_count, already covered by junction_density
  • a_road_length_m → keep pct_a_road instead
  • area_km2 → drop since road_density already accounts for geographic area

For cycling variables, since 95.6% are zeros, I’ll recode into a binary has_cycle_infra flag and drop the raw length variable.

So my final clustering variable set: road_density, pct_a_road, junction_density, mean_speed_limit_mph (still need to resolve overlap with pct_20mph and median_speed_limit), pct_20mph_or_less, pct_30mph_or_less, mean_avg_speed_am_mph, and has_cycle_infra.

Checking correlations, mean_speed_limit_mph with pct_20mph_or_less and median_speed_limit_mph both fall just under the 0.90 threshold, so step_corr won’t automatically drop them — I’ll leave that decision to the recipe for now.

For count-versus-density pairs, I’ll drop the raw counts like hh_no_car, unemployed_count, imd_decile, road_length_m, junction_count, road_link_count, a_road_length_m, and area_km2, keeping the normalized versions instead: pct_no_car, unemployment_rate, imd_rand, road_density_km_per_km2, junction_density_per_km2, and pct_a_road. Cycling infrastructure gets recoded to a binary has_cycle_infra flag, and I should also exclude denominator fields like hh_total and pop_16_plus since they’re just used to compute rates rather than being clustering variables themselves.

I’m also dropping bus_stop_count in favor of bus_stop_density_per_km2 for comparability, and considering whether median_speed_limit_mph is too correlated with mean_speed_limit to keep both.

So the final variable set includes road density, A-road density, junction density, speed limit measures (mean and median mph, plus percent under 20/30mph), cycle infrastructure presence, distance to city centre, IMD rank, bus stop density, population density, and percent of households without a car.

I’m also adding unemployment rate to the keep list, while dropping the raw geographic and count variables that got absorbed into density measures — area, road length, A-road length, link counts, junction counts, cycle infrastructure length, IMD decile, and bus stop counts — since those are now redundant denominators behind the density variables I’m keeping.

That leaves 15 variables for clustering, which feels like a reasonable set. Now I’m moving to the code: I’ll put the variable selection and transformation logic in the “what-next” chunk, manually recoding things like cycling infrastructure into a binary presence/absence flag, and then update the standardise chunk to actually run instead of being skipped.

3 Standardise variables

Recipe specification with:

  1. Zero-variance removal
  2. Median imputation
  3. Normalization to mean=0, sd=1
  4. Correlation filtering (threshold=0.90)
Code 
rec_lsoa <- recipe(~ ., data = df_lsoa_clean) |>

  # LSOA identifier (retain but exclude from modelling)
  update_role(LSOA21CD, new_role = "id") |>

  # Remove zero-variance predictors
  step_zv(all_numeric_predictors()) |>

  # Impute any remaining missing values
  step_impute_median(all_numeric_predictors()) |>

  # Standardise all predictors to mean = 0, sd = 1
  step_normalize(all_numeric_predictors()) |>

  # Remove highly correlated variables
  step_corr(
    all_numeric_predictors(),
    threshold = 0.90
  )

# Prepare recipe
rec_lsoa_prep <- prep(rec_lsoa)

# Create clustering dataset
df_cluster <- bake(
  rec_lsoa_prep,
  new_data = NULL
)

# Predictor matrix for clustering
x_cluster <- df_cluster |>
  select(-LSOA21CD)
